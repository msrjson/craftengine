Medido

Craft foi auditado nesta própria sessão: leitura direta do código-fonte em services/, mais um teste de carga real (ThreadPoolExecutor, concorrência 1→100) contra o container rodando. Não é opinião — é o que o framework fez quando testado.

Estimativa de mercado

Os demais frameworks foram pontuados pela postura padrão bem documentada de cada um (o que vem de fábrica, não com pacotes de terceiros) — não foram re-executados nesta sessão. Trate como leitura de posicionamento, não como benchmark de laboratório equivalente ao de Craft.

Pontuação composta

Média simples das 6 dimensões — um número não substitui a grade acima, mas ordena a conversa.

Onde o Craft compete de verdade: segurança primitiva (CSRF, sessão, hash de senha, defesa contra SQLi) e, principalmente, prontidão para agentes de IA — nenhum concorrente listado tem o equivalente à biblioteca de skills e à disciplina de CHANGELOG obrigatório que este projeto construiu. É a única dimensão onde o Craft lidera o grupo, não só participa.

Onde perde feio, e por quê é medido, não achismo: escalabilidade. O teste de carga real mostrou throughput constante em ~30 req/s independente da concorrência (1 a 100 clientes) — assinatura de processamento totalmente serializado. Nenhum dos seis concorrentes roda em produção com processo único e conexão de banco compartilhada por padrão; é aí que a distância é maior.

Admin/scaffolding de UI é o segundo maior gap — Django dá tela de admin de graça a partir do model; o CRUD builder do Craft ainda gera só API JSON. Já corrigido nesta sessão: as rotas de escrita geradas agora exigem autenticação real (antes, API pública de exclusão por padrão).
